## 0. القرارات المعتمدة

| القرار | المعتمد |
|---|---|
| النطاق | معالج تسجيل متفرّع + الأوصاف الثلاثة + لوحة هوية بصرية مفصّلة |
| الاستخراج التلقائي | صورة المنتج (رؤية) **و** رابط المتجر (الكرولر الحالي) معاً |
| علاقة الهوية بالمنتج | المعالج ينشئ `Brand` + أول `Product` + `ProductImage` في معاملة واحدة |
| إعادة التوليد | تعيد التوليد من الإجابات الحالية، **وتحفظ النسخة السابقة** — للمستخدم أن يعود إليها أو يحذفها |

### افتراضات اتخذتها (اعترض عليها قبل التنفيذ إن خالفت رأيك)

1. **نظام التصميم:** نبقى على توكنز المشروع (`field`, `x-section`, `border-line`, `bg-muted`) ونستعير من المرجع أنماطه لا ألوانه: بطاقة لكل مجموعة، شارة «المفضل»، بلاطة منقّطة للإضافة، مثال حقيقي في كل placeholder.
2. **التخزين:** جدول مستقل `brand_logos` (لكل شعار ملف وحالة تفضيل)، وJSON داخل `brands` للألوان والخطوط والأنماط.
3. **النقاط:** `brand.profile` = 2 · `brand.vision_extract` = 1 · الاستعادة والحذف بلا تكلفة.
4. **التخطي:** مسموح كما في المرجع. `EnsureBrandIsReady` يتوقف عن الحجز الكامل: يسمح بالتصفح مع شريط «هويتك ناقصة»، ويمنع التوليد فقط.

## 0.1 قرار الدمج (2026-09-21)

صفحتا «هوية العلامة» (القديمة) و«ملف المشروع» دُمجتا في صفحة واحدة باسم **هوية العلامة** على `/brand/profile`:

| القرار | المعتمد |
|---|---|
| مصدر الإجابات | أعمدة `brands` وحدها. لقطة `answers` في كل نسخة سجلٌّ لما وُلدت منه فقط |
| الحقائق في الوصف التقني | النوع والاسم والرابط تُقرأ حيّةً من العلامة (`technicalFor`) — تصحيحها يصل لكل النسخ |
| تعديل الإجابات | حفظ مجاني بلا توليد + تنبيه «الأوصاف لا تعكس آخر تعديلاتك». الاستثناء: أول حفظ ينشئ الأوصاف مجاناً |
| الأسئلة | النوع · الاسم · الرابط · ماذا تبيع · الميزة التنافسية · **الجمهور** · الملاحظات. «المجال» لم يعد سؤالاً ويُكتب من `activity_type` |
| إعدادات الكتابة | اللهجة · النبرة · الكلمات الممنوعة · واتساب: حفظ مستقل، لا توليد ولا تأخر |
| الاستعادة | الأوصاف فقط؛ الإجابات والحقائق تبقى الحالية |
| البرومبت | مع وجود ملف: الاسم والمجال والنبذة والمزايا والرابط منه وحده، ومن العلامة الجمهور والنبرة وواتساب فقط |
| `/brand/setup` | يعيد التوجيه إلى `/brand/profile`. `BrandController` و`wizard.blade.php` حُذفا |

## 1. البنية: هويتان لا واحدة

النموذج المرجعي يفصل ما نخلطه اليوم في صفحة واحدة:

| الطبقة | تُجمع في | تُخزَّن في | تُستهلك في |
|---|---|---|---|
| **هوية المشروع (نصية)** | المعالج، مرة واحدة، بأقل احتكاك | `brand_profiles` (نسخ) | `PromptBuilder::brandLayer()` |
| **الهوية البصرية** | لوحة إعدادات مستقلة، بالتدريج | `brands` + `brand_logos` | استوديو الصور وتركيب الشعار |

الفصل عملي لا تجميلي: النصية تُسأل مرة ولا تُلمس غالباً، والبصرية تُعدَّل كثيراً وتحتاج صفحة تعيش وحدها.

## 2. المخطط

### 2.1 جدول جديد: `brand_logos`

```
id · brand_id (cascade) · path · label nullable
is_default bool default false · sort unsignedTinyInt default 0 · timestamps
index(brand_id, sort)
```

- شعار افتراضي واحد لكل علامة، يُضبط في الخدمة لا في القيد.
- `brands.logo_path` **يبقى كما هو** ويُحدَّث تلقائياً عند تغيير المفضّل (Observer). السبب: يقرأه اليوم `resources/views/partials/sidebar.blade.php` وغيره، ولا داعي لكسرها.

### 2.2 جدول جديد: `brand_profiles`

```
id · brand_id (cascade) · version unsignedInt · is_active bool
answers json          -- اللقطة الخام كما كتبها المستخدم
simple text           -- الوصف المبسط
detailed longText     -- الوصف التفصيلي
technical json        -- الوصف التقني (شظية برومبت)
source enum(generated|manual_edit|restored)
generation_job_id nullable · created_at · updated_at
unique(brand_id, version) · index(brand_id, is_active)
```

شكل `answers`:

```json
{
  "project_name": "…", "store_url": "…|null",
  "one_liner": "…", "advantages": "…", "notes": "…|null"
}
```

شكل `technical` — مفاتيح ثابتة، وهي حرفياً ما يُحقن في البرومبت:

```json
{
  "project_type": "سلع|خدمة",
  "project_name": "…",
  "activity_type": "…",
  "sales_summary": "…",
  "advantages_directives": "…",
  "important_notes": ["لا تذكر أي تفاصيل غير واردة في المدخلات", "…"],
  "store_url": "…|null"
}
```

`important_notes` قواعد سالبة يقرأها النموذج في كل توليد لاحق، وهي قابلة للتحرير من الواجهة. هذه هي الفكرة المركزية في النظام المرجعي: جزء من الـ system prompt يعيش في قاعدة البيانات لا في الكود.

### 2.3 تعديلات على `brands`

```
fonts json nullable            -- {ar_primary, ar_secondary, en_primary, en_secondary}
patterns json nullable         -- [{path, sort}] بسقف 6
design_summary text nullable   -- الخلاصة التصميمية، تُحقن في برومبت الصور
```

و**تغيير شكل `colors`** من `["#6F4E37"]` إلى:

```json
[{"hex": "#6F4E37", "name": "بني القهوة", "role": "primary"}]
```

الهجرة تحوّل القديم: أول لون يصبح `primary` والبقية `secondary`، والاسم `null`. الأدوار: `primary · secondary · accent · background · text`.

### 2.4 لا تغيير على `products`

الحقول المطلوبة موجودة أصلاً (`type`, `features`, `specifications`, `audience`, `deliverables`, `notes`) من هجرة الحقول المرجعية `2026_01_02_000100_add_reference_fields_to_products_table.php`.

## 4. المعالج، خطوة بخطوة

| # | الشاشة | الحقول | التحقق | ملاحظة التنفيذ |
|---|---|---|---|---|
| 1 | **يا هلا فيك** | اسم النشاط · اللهجة | `required max:120` · `in:saudi,gulf,egyptian,msa` | حقلان فقط. اللهجة تُشرح في الليبل: «تُستخدم لاحقاً في الفويس أوفر» |
| 2 | **وش طبيعة نشاطك؟** | بطاقتان: سلعة / خدمة | `in:good,service` | بطاقتان كبيرتان بأيقونة، لا dropdown. القيمة تُخزَّن في `products.type` وتغيّر صياغة الخطوة 4 |
| 3 | **ارفع صورة منتجك** | صورة المنتج (إلزامية) · الشعار (اختياري) | `image max:10240 mimes:png,jpg,webp` · الشعار `max:2048` | «التالي» معطّل حتى يُرفع الإلزامي. بعد الرفع: معاينة + ✓ «تم الرفع — اضغط لتغيير» + × أحمر. عند الضغط يُطلق `ExtractBrandFactsJob` في الخلفية بينما يكتب المستخدم |
| 4 | **الأسئلة الأربعة** | رابط المتجر (اختياري) · سطر واحد عمّا تبيع · أهم ميزة تنافسية · ملاحظات إضافية | `url nullable` · `required max:300` · `required max:600` · `nullable max:1000` | تُملأ مسبقاً من نتيجة التحليل إن جهزت، مع شارة «عبّأها الذكاء — عدّلها إن لزم». غير المُجاب يُحفظ حرفياً كـ `"لم يتم الإجابة"` لا كـ null |
| 5 | **المعالجة** | — | — | استطلاع على `JobStatusController` الحالي ثم تحويل لصفحة النتائج |

صياغة السؤالين حسب النوع:

- **سلعة:** «في سطر واحد، وش تبيع؟» · «أهم ميزة تنافسية لديكم؟»
- **خدمة:** «في سطر واحد، وش الخدمة اللي تقدمها؟» · «وش يستلمه العميل منك بالضبط؟» ← تذهب إلى `products.deliverables`

ثوابت عبر الخطوات: شريط تقدّم · «تخطي» في الأعلى · «رجوع» أسفل · الحالة محفوظة في الجلسة حتى لا يضيع التقدّم عند الإغلاق.

## 5. خط توليد الملف

خدمة `App\Services\Brand\BrandProfileGenerator`:

```
الإجابات الأربع
+ صورة المنتج        → رؤية: نوع المنتج، الخامة، الاستخدام، الفئة
+ رابط المتجر        → StoreCrawler الحالي: العنوان، الوصف، الفئة
+ أساسيات العلامة     → الاسم، المجال، اللهجة، النبرة
        ↓ AiManager::generateText بمخطط JSON مُلزم
{ simple, detailed, technical{…} }
        ↓
نسخة جديدة في brand_profiles + تحديث حقول products من نفس الاستدعاء
```

قواعد ملزمة في برومبت النظام لهذه العملية تحديداً:

- لا تُضِف معلومة غير واردة في المدخلات — ولا حتى ما «يُستنتج عادةً» عن هذا النوع من النشاط.
- الوصف المبسط: فقرة واحدة، ≤ 60 كلمة، بلا مبالغات ولا صفات تفضيلية مطلقة.
- الوصف التفصيلي: 120–200 كلمة، يذكر الفئات والجمهور وقنوات البيع الواردة فقط.
- الوصف التقني: تلغرافي لا تسويقي — يُقرأ آلياً لا بشرياً.
- `banned_words` من العلامة تُحقن هنا أيضاً.

إعادة الاستخدام: نفس نمط `ProductEnricher` — مخطط JSON + `JsonExtractor` + تسجيل في `ai_usage_logs`.

## 6. الإصدارات: القواعد

| الحدث | السلوك |
|---|---|
| توليد ناجح | نسخة جديدة `version = max+1`، `source=generated`، تصبح النشطة |
| تحرير يدوي لوصف | إن كانت النشطة `generated` → تُنسخ إلى نسخة جديدة `manual_edit` ثم يُطبَّق التعديل (فتبقى نسخة الذكاء سليمة). إن كانت `manual_edit` أصلاً → تحديث في مكانه |
| استعادة نسخة قديمة | **تُنسخ إلى الأعلى** كنسخة جديدة `source=restored` بدل إرجاع المؤشر. التاريخ يبقى خطياً ولا تُفقد النسخة الحالية |
| حذف نسخة | مسموح لغير النشطة فقط. لحذف النشطة: استعد غيرها أولاً |
| السقف | نحتفظ بآخر 10 نسخ لكل علامة (`config('brand.profile_versions')`) ونحذف الأقدم تلقائياً |
| «حذف والبدء من جديد» | يحذف كل النسخ والإجابات ويعيد فتح المعالج. نافذة تأكيد بكتابة اسم العلامة |

واجهة التاريخ: قائمة مبسطة (رقم النسخة · المصدر · التاريخ · أول 80 حرفاً من الوصف المبسط) مع زري «استعادة» و«حذف».

## 7. توسيع طبقة الذكاء للرؤية

اليوم `TextRequest` لا يقبل صوراً إطلاقاً. المطلوب:

```php
class TextRequest {
    public function __construct(
        public string $system,
        public string $prompt,
        public ?array $schema = null,
        public float $temperature = 0.8,
        public int $maxTokens = 2048,
        public string $operation = 'content.post',
        /** @var array<int, array{disk:string, path:string, mime:string}> */
        public array $images = [],   // ← جديد
    ) {}
}
```

- `AnthropicTextProvider`: كتل `image` بـ base64 داخل رسالة المستخدم.
- `OpenAiTextProvider`: `image_url` بصيغة data URI.
- `FakeTextProvider`: يتجاهل الصور ويعيد نصاً ثابتاً — الاختبارات تبقى تعمل بلا مفاتيح.
- سقف: صورتان كحد أقصى (المنتج + الشعار)، وتصغير إلى 1024px قبل الإرسال توفيراً للتوكنز.

`.env` اليوم على `AI_TEXT_PROVIDER=fake` — يلزم مفتاح حقيقي لاختبار المسار كاملاً.

## 8. لوحة الهوية البصرية

بطاقة لكل مجموعة، وحفظ صريح واحد أسفل الصفحة (لا autosave):

1. **مكتبة الشعارات** — شبكة بطاقات + بلاطة «إضافة شعار» منقّطة. كل بطاقة: معاينة، اسم، شارة «المفضل» على الافتراضي، أيقونتا تعديل وحذف.
2. **الألوان** — صف لكل لون: منتقي لون + حقل HEX (`dir="ltr"`) + اسم اللون + قائمة الدور + زر حذف، ثم «+ إضافة لون».
3. **الأنماط والأشكال (حتى 6)** — شبكة رفع، والعنوان يعلن السقف صراحة.
4. **الخطوط** — أربعة حقول بأمثلة: Cairo · Tajawal · Inter · Roboto.
5. **الخلاصة التصميمية** — نص حر مع مثال طويل في الـ placeholder.

مكان الحقن: برومبت الصور في استوديو الصور — الألوان بأدوارها، والخلاصة كتوجيه أسلوبي، والشعار المفضّل للتركيب.

## 9. حقن الهوية في البرومبت

`PromptBuilder::brandLayer()` يتوقف عن تركيب الحقول يدوياً ويقرأ النسخة النشطة:

```php
protected function brandLayer(): ?string
{
    $profile = $this->brand?->activeProfile;

    return $profile
        ? "## العلامة التجارية\n".$profile->toPromptFragment()
        : $this->legacyBrandLayer();   // علامات ما قبل الترقية
}
```

`toPromptFragment()` يسرد مفاتيح `technical` بالعربية سطراً سطراً، و`important_notes` تُلحق بطبقة النظام لا بطبقة المستخدم — لأنها قيود لا توجيه إبداعي، وهذا يحترم ترتيب الطبقات الموثّق في `PromptBuilder`.

## 10. النقاط

```php
'brand.profile'        => 2,   // توليد أو إعادة توليد الأوصاف الثلاثة
```

التوليد الأول داخل المعالج **مجاني** (يُخصم صفر) — لا نطالب بنقاط قبل أن يرى المستخدم قيمة. إعادة التوليد لاحقاً مدفوعة، والتكلفة معروضة على الزر نفسه.

## 13. مخاطر

- **الرؤية بلا مفتاح:** كل المسار يعمل على `fake` لكنه لا يُثبت شيئاً. نحتاج مفتاحاً حقيقياً قبل نهاية الدفعة 3.
- **شكل `colors` يتغير:** أي كود يقرأ `$brand->colors` كمصفوفة نصوص سيُكسر. البحث تم: القارئ الوحيد اليوم هو `wizard.blade.php` الذي سيُفكَّك أصلاً.
- **تضخم النسخ:** السقف 10 يعالجه، لكن `answers` تُكرَّر في كل نسخة. مقبول (كيلوبايتات)، والبديل (جدول إجابات منفصل) يعقّد الاستعادة.
- **التخطي يخلق علامات ناقصة:** يلزم شريط تنبيه دائم وقفل صريح على أزرار التوليد، وإلا وصلنا إلى برومبتات فارغة وشكاوى جودة.

## 14. الجودة والموثوقية (2026-09-21)

| الطبقة | السلوك |
|---|---|
| **فحص الجودة** | `ProfileQualityCheck`: رقم أو رابط غير وارد في الإجابات، كلمة ممنوعة، نص تجريبي، حقل فارغ = **خطأ**. مبالغة، طول، Markdown، لغة، اسم غائب، عدد الملاحظات = **تحذير** |
| **بوابة وقت التشغيل** | خطأ في المسودة ← طلب تصحيح واحد يسمّي المشاكل (حرارة 0.3) ← يُحفظ الأقل أخطاءً. ما بقي يظهر في الصفحة «راجع هذه النقاط». فشل طلب التصحيح لا يُسقط المهمة. التصحيح لا يُخصم من نقاط المستخدم |
| **حقل `quality`** | في كل نسخة مولّدة: الدرجة والمشاكل وعدد المحاولات. التحرير اليدوي يمسحه (النص صار نص المستخدم)، والاستعادة تنسخه |
| **القطع** | عند آخر نهاية جملة قبل الحد؛ «…» فقط إن لم توجد نهاية جملة |
| **مخطط Gemini** | `responseSchema` (أنواع بأحرف كبيرة، مفاتيح غير مدعومة تُسقط). إن رُفض المخطط (400) يُعاد الطلب مرة بلا قيد |
| **إعادة المحاولة** | 429 بحصة يومية أو نفاد رصيد: **لا إعادة** وتُنهى المهمة فوراً. 429 بحد الدقيقة: إعادة بعد المهلة التي يطلبها المزود (حتى 10 ثوانٍ). 5xx: إعادة |
| **رسائل الفشل** | `ProviderException::userMessage()`: بلا JSON، وتذكر إرجاع النقاط |
| **انتهاء مهلة الاستطلاع** | ليست فشلاً: «يستغرق أطول من المعتاد… نكمل في الخلفية» |
| **المهام العالقة** | `ai:reap-stuck-jobs` كل 5 دقائق: مهمة بلا تقدم 15 دقيقة (`AI_STUCK_AFTER_MINUTES`) تُنهى وتُرجع نقاطها. يتطلب تشغيل المجدول |
| **التعبئة من الرابط** | `POST /brand/profile/prefill` متزامن: نقطة واحدة (مجاني قبل إنشاء العلامة)، `throttle:6,10`. يملأ الفارغ فقط، ولا يحفظ |
| **تلميحات الإدخال** | وصف أقل من 5 كلمات، ميزة عامة («جودة عالية»)، جمهور مبهم («الجميع») ← تنبيه غير مانع |
| **التقييم الحي** | `php artisan brand:eval-profile --show` على 4 مشاريع نموذجية بالنموذج المضبوط؛ لا يحفظ ولا يخصم نقاطاً |

## 15. منهجية البرومبت (2026-09-25)

الشكوى: الأوصاف «ركيكة» مقارنة بالمنافسين. السبب في البرومبت نفسه: قدّم «الدقة على البلاغة» وقال إن الملف «لا يُنشر»، بينما الوصفان يُنشران حرفياً في البايو و«من نحن» — فخرجا سرداً مسطحاً للإجابات.

| القرار | المعتمد |
|---|---|
| **الدور** | استراتيجي علامات وكاتب إعلانات عربي، لا «محلل» يلخّص |
| **القارئ** | `simple`/`detailed` نص تسويقي يقرؤه العميل؛ الحقول التقنية موجز تلغرافي لكاتب آلي |
| **التفكير قبل الكتابة** | حقل `brief` أول المخطط: الحاجة · الوعد الجوهري · الأدلة · الزاوية. لا يُحفظ؛ يظهر في `brand:eval-profile --show`. Gemini يلتزم الترتيب عبر `propertyOrdering` |
| **من الميزة إلى الفائدة** | الفائدة نتيجة مباشرة لحقيقة واردة، بأمثلة المسموح والممنوع داخل البرومبت |
| **`advantages_directives`** | سطر لكل ميزة: «الميزة ← الفائدة ← متى تُبرز». أكثر حقل يرفع جودة المحتوى اللاحق |
| **العبارات المستهلكة** | `config('brand.profile_cliches')`: يمنعها البرومبت، ويحذّر منها الفحص (`cliche`، تحذير لا خطأ) — مصدر واحد. ما كتبه التاجر نفسه لا يُحذَّر منه |
| **النبرة** | `brand->tone` تُمرَّر (روح الكتابة)؛ اللهجة لا تزال لا تُمرَّر (الأوصاف فصحى) |
| **المدخلات الشحيحة** | «أقصر وأدق» بدل حشو يصل لـ120 كلمة بالاختلاق |
| **التعبئة من الرابط** | الميزة بقيدها حرفياً («فوق 200 ريال»)، وتجاهل الشعارات العامة، والفئات كما تظهر في الأقسام |
| **نموذج الهوية** | `AI_PROFILE_PROVIDER` و`AI_PROFILE_MODEL` (`config('ai.profile')`): الهوية وحدها لنموذج مخصص، والمحتوى يبقى على الافتراضي. النموذج يُمرَّر في `TextRequest::model` كالتدقيق اللغوي، والنموذج وحده يكفي مع المزود الافتراضي. مزود بلا مفتاح أو نموذج مرفوض (400/404) ← الافتراضي بتحذير في السجل. `brand:eval-profile` يمر بالتوجيه نفسه |
| **تقرير التقييم** | `brand:eval-profile` يكتب في كل تشغيل `storage/app/brand-eval.html` (أو `--html=`): من اليمين لليسار، بالمدخلات والموجز والأوصاف والمشاكل. طرفية ويندوز تعرض العربية معكوسة الحروف ومتقطعة |
| **إصدار البرومبت** | `BrandProfileGenerator::PROMPT_VERSION` يُحفظ في `quality.prompt_version`، ومصدر **كل حقل تقني** في `quality.technical_versions` (`BrandProfile::technicalVersions()`): الحقل الباقي من نسخة سابقة يحمل مصدره لا ختم النسخة. ما كتبه برومبت أقدم يُعاد عند إعادة التوليد وإن لم تتغير الإجابات. ما حرّره التاجر («manual») يبقى في كل توليد تالٍ؛ وتعديل الوصف المبسط وحده لا يجعل الوصف التقني يدوياً (يُقارن بآخر نسخة آلية). النسخ القديمة بلا خريطة: الحقل في `kept` = قديم. رُصد في توليد حقيقي (2026-09-26): v16 مختومة بالإصدار 3 ووصفها التقني من الإصدار 1 |
| **ما كشفه أول توليد حقيقي (v3)** | الصوت: «نحن» للعميل «أنت» بلا خلط مع «المتجر». جمّع الأصناف في عائلات (المبسط ≤ 3). الفائدة منسوجة لا قالب «كون… يعني أن». الحقيقة غير اللائقة لفظاً تُصاغ من زاوية العميل. جمهور أول ثم جملة للبقية. مثال ضعيف/قوي من مشروع آخر داخل البرومبت. تراكيب مترجمة أُضيفت لـ `profile_cliches` |
| **مرجع المطوّر** | `.claude/skills/brand-identity/SKILL.md`: الثوابت، والمنهجية، وقائمة الصنعة، وحلقة التقييم |
